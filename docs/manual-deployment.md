# Cloudflare 控制台手动部署

## 1. 准备

- 一个可使用 Workers 和 KV 的 Cloudflare 账户。
- 若使用自定义域名，该域的 DNS 区域应已在同一 Cloudflare 账户中托管。
- 本项目的完整 `worker.js` 文件。

本次实例名称为 `kimari-sub5`，自定义域名为 `sub5.kimari.top`。部署其他实例时可以换名称和域名，并为每个实例创建独立 KV。

## 2. 创建 Worker 与发布代码

1. 进入 Cloudflare 控制台 → Workers 和 Pages → 创建应用程序。
2. 选择“从 Hello World! 开始”。
3. 输入 Worker 名称，例如 `kimari-sub5`，点击部署。
4. 打开该 Worker，点击“编辑代码”。
5. 在代码编辑器中打开 `worker.js`，选中全部默认代码。
6. 用本项目 `worker.js` 的**全部内容**替换，点击“部署”。

该源码已经包含管理页，无需 npm 安装、构建或单独部署 HTML。文件末尾包含 `export{ef as default,oi as remote,wn as validate};`，请勿仅复制网页部分或截断文件。

## 3. 创建独立 KV

1. 进入“存储和数据库” → Workers KV。
2. 点击“创建 KV 命名空间”。
3. 输入名称，例如 `sub5-kimari-config`，点击创建。

新命名空间可以保持为空，应用会自动提供默认配置。不要绑定其他正在使用的实例的 KV，否则实例会共享配置。

## 4. 绑定 KV

1. 返回新 Worker → 设置 → 绑定 → 添加绑定。
2. 选择“KV 命名空间”。
3. 变量名称填写 **`CONFIG`**，大小写必须一致。
4. 生产命名空间选择刚创建的 `sub5-kimari-config`。
5. 预览可以勾选“使用生产值”，也可使用另一个测试命名空间。
6. 点击“添加绑定”，等待保存完成。
7. 确认绑定列表显示 `CONFIG` → `sub5-kimari-config`。

代码只识别 `env.CONFIG`。命名空间本身的名称可以自定义，绑定变量名必须是 `CONFIG`。

## 5. 自定义域名

1. 打开 Worker 的“域”页面 → “添加域名”。
2. 在区域搜索中输入主域 **`kimari.top`**，选择已有区域。
3. 在“子域名”输入 **`sub5`**。
4. 启用对象选择“生产”，点击“添加域名”。
5. 确认域列表显示 `sub5.kimari.top`。
6. 打开 `https://sub5.kimari.top/YOUR_ENTRY_PATH`。

区域搜索输入主域，子域名单独填写。控制台会管理 Worker 自定义域的 DNS 和证书；以实际 HTTPS 访问成功作为完成依据。

也可用 Worker 的 `workers.dev` 地址测试，但需要带上 `/YOUR_ENTRY_PATH`。当前程序在根路径 `/` 返回 `Not found`，这是入口限制的预期行为。

## 6. 登录、保存与订阅

1. 输入你在源码中设置的管理密钥，进入管理页。
2. 添加你的订阅来源、单节点链接或本地配置文件。
3. 点击“检查来源 / 预览”，检查解析数量和提示。
4. 点击“保存配置”，确认显示保存成功。
5. 复制页面生成的固定订阅地址，在 Clash / Mihomo 客户端导入并更新。

占位订阅地址（部署前替换路径和订阅密钥）：

```text
https://sub5.kimari.top/YOUR_ENTRY_PATH/sub?token=YOUR_SUBSCRIPTION_KEY
```

这里的 YOUR_SUBSCRIPTION_KEY 是订阅密钥占位值，不是 Cloudflare API Token。修改密钥后以页面显示的地址为准。空配置没有可用节点，下载订阅会返回“没有可用节点”，需先添加并保存真实来源。

## 7. 验证清单

- HTTPS 管理入口能打开。
- 正确密钥能登录，错误密钥不能登录。
- 登录后能看到固定订阅地址及默认分组，说明配置接口与 KV 绑定可用。
- 保存后显示成功，重新加载页面仍保留设置。
- 有有效节点时，客户端可拉取订阅。

KV 跨地区同步可能需要约一分钟。上游订阅拉取失败时，检查地址和页面提示；裸 IP 来源可能受 Workers 限制，可以使用上游域名地址或导入本地文件。

## 更新与备份

更新前使用管理页“备份设置”保存配置，并保留上一版 `worker.js`。更新时只替换新 Worker 的代码，保持该实例的 `CONFIG` KV 绑定不变。恢复时部署此前源码，并按需要使用“导入设置”恢复配置。
